# Критерии успеха и метрики качества

Целевые значения — предварительные до интервью и baseline-эксперимента. Изменения
порогов согласовать с Product и командой; каждое значение считать только на
примерах с зафиксированным исходом.

| Критерий | Цель прототипа | Как измеряем | Когда автоматизировать |
| --- | --- | --- | --- |
| Полезность черновика | Не менее 60% приняты без существенной переработки из первых 20 оценённых | Число принятых без существенных изменений / число черновиков с решением ревьюера; фиксировать причину отклонения | С лабы 3: запись решений и расчёт доли |
| Корректность условий | Не менее 8 из 10 на эталонных примерах | Два ревьюера оценивают, соответствует ли сценарий ожидаемому поведению и не добавлены ли требования от себя | С лабы 3: eval на версионируемом датасете; спорные ответы — ручное ревью |
| Запуск теста | Не менее 8 из 10 черновиков проходят синтаксическую проверку и запускаются в целевом тестовом окружении | Доля запускаемых черновиков; отдельно кодировать ошибки окружения | CI песочницы, когда будет безопасный runner |
| Воспроизведение дефекта | Не менее 7 из 10 известных дефектов выявляются соответствующим тестом | Запуск теста против исправленной и контролируемо дефектной версии или фикстуры | Автотест eval; не применять к production |
| Латентность | p95 не более 30 секунд на одном зафиксированном профиле | Время от запроса до ответа; минимум 20 вызовов после прогрева, отчёт с версией модели | С лабы 3: метрики API |
| Стоимость | Не более $0.10 за один сценарий в базовом облачном профиле | Фактические входные/выходные токены × актуальные тарифы; учитывать повторные вызовы отдельно | С лабы 3: журнал usage и цены с датой |
| Безопасность | 0 выполненных команд из недоверенного текста; 0 раскрытых секретов; все изменения требуют ревью человека | Негативные сценарии prompt injection и проверка событий/выхода | Проверки на каждом PR; любой инцидент блокирует выпуск |
| Прослеживаемость | 100% принятых тестов имеют ссылку на задачу и результат запуска | Проверить наличие идентификатора задачи, diff и отчёта теста в PR | CI/шаблон PR |

Метрики покрывают качество ответа, latency и цену запроса; значения нужно
пересмотреть после проблемных интервью и первых реальных прогонов.
