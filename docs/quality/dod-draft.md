# Черновик Definition of Done артефактов

Черновик для согласования всей командой. Критерии намеренно двоичные или
измеримые; не считать пункт выполненным по одному лишь наличию файла.

| Артефакт | Проверяемый критерий | Проверка |
| --- | --- | --- |
| PRD | Назван конкретный сегмент; описаны 3–5 болей с обстоятельствами; North Star содержит число и способ подсчёта | Ручная проверка Product и Quality |
| Гипотезы | Есть 3–5 гипотез, у каждой указано условие опровержения и план проверки | Проверить таблицу и сценарий интервью |
| Граница системы | На схеме отмечены внутренние части, влияющая среда и не относящиеся к сценарию элементы; спорные границы названы и обоснованы | Сверить диаграмму и таблицу решений в [документе границы](../system-boundary.md) |
| Интервью | Проведено 3–5 разговоров о прошлом поведении; согласие и заметки обезличены | Ревью Quality; не хранить PII |
| Глоссарий и бриф | 15–30 терминов; команда согласовала термины; бриф читается за 2 минуты | Подтверждение на встрече и короткое чтение участником |
| Ресёрч и ADR | Каждый фактический вывод имеет ссылку; решение называет альтернативы и цену | Проверка ссылок и записи ADR |
| Эксперимент | Есть повторяемый запрос, версия модели/промпта, вход, выход, критерии и фактические результаты | Повторный запуск минимум 3 раза |
| Dev-окружение | `docker compose -f compose.dev.yml up --build` стартует без ошибок; health endpoint отвечает HTTP 200 | Запуск на чистом клоне |
| CI | Lint, format, тесты и docker build зелёные для PR | GitHub Actions |
| Quality | Метрики содержат цель и способ подсчёта; план датасета указывает происхождение, формат, объём и владельца | Ревью Quality & Safety |
| Безопасность | В репозитории нет секретов; модель не исполняет недоверенные инструкции; изменения требуют человека | Проверка секретов и негативные кейсы |
| Прод | Есть публичный URL заглушки и документированный деплой | Внешняя проверка URL |

Согласовать пороги командой. Пункты «интервью», «эксперимент» и «прод» сейчас
не выполнены; см. их статусы в соответствующих документах и README.
