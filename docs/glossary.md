# Глоссарий команды

Черновик для согласования вслух всей командой. Если команда использует термин
иначе, обновить определение и применять его одинаково в PRD, брифе и коде.

| Термин | Определение в рамках проекта |
| --- | --- |
| Требование | Описание нужного поведения или ограничения продукта, которое можно уточнить и проверить. |
| Багрепорт | Сообщение о наблюдаемом отклонении с контекстом, шагами или данными для воспроизведения. |
| Проверяемое условие | Утверждение о поведении системы, для которого можно задать вход и однозначно оценить результат. |
| Тестовый сценарий | Описание условий, входных данных, действий и ожидаемого результата проверки. |
| Тест | Исполняемая проверка одного или нескольких условий в кодовой базе. |
| Регрессионный тест | Тест, который сохраняет проверку исправленного поведения и помогает заметить повтор дефекта. |
| Ожидаемый результат | Заранее заданное наблюдаемое поведение, с которым сравнивается фактический результат. |
| Тестовый оракул | Правило или источник истины, по которому решают, правильный ли результат получен. |
| Фикстура | Подготовленное окружение или набор данных, используемый тестом. |
| Flaky-тест | Тест, результат которого меняется между запусками без соответствующего изменения проверяемого кода или условий. |
| Покрытие тестами | Метрика выполненных участков кода или требований; сама по себе не доказывает полезность тестов. |
| Черновик теста | Предложенный системой, но ещё не принятый человеком тест или сценарий. |
| Pull request (PR) | Запрос на проверку и слияние изменений в репозиторий; в проекте это граница человеческого контроля. |
| Ревью | Проверка человеком корректности, уместности и безопасности предложенных изменений. |
| Golden dataset | Версионируемый набор входов и согласованных эталонных ответов для оценки системы. |
| Eval | Повторяемая оценка качества системы на заданном наборе примеров по определённым критериям. |
| Prompt injection | Попытка повлиять на поведение модели через недоверенный текст, например содержимое задачи или файла. |
| Least privilege | Принцип минимальных полномочий: компонент получает только доступ, необходимый для своей задачи. |
| Латентность p95 | Время ответа, быстрее которого завершаются 95% измеренных запросов. |
| Стоимость сценария | Расход на один сценарий, рассчитанный по токенам и тарифам выбранной модели. |
| Прослеживаемость | Возможность связать тест и результат его запуска с исходным требованием или багрепортом. |
